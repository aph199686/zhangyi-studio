# 张翼工作台方案（草案 · 2026-09-26）

## 要解决的事

玩家可以只说“我喜欢这款游戏，想做一个这样的”，无需先懂策划术语或提出创新点。
张翼把想法逐步变成可选、可试玩、可修改的方案；每一步的依据和状态可见。
当方向成熟，工作台导出供不同 AI 助手或开发者接手的项目包。

**定位**：工作台是张翼 skill 的可视界面与项目记忆。张翼仍负责提出草案、判断取舍、
说明代价和发现矛盾；界面负责选择、回看、修改、试玩入口与导出。

**运行边界**：现有 `nest/index.html` 是离线阅读器。第一批 HTML 可以本地保存选择、
下载项目包、导入 AI 助手返回的记录；若要在页面里实时调用张翼并自动写入项目文件，
还需要明确的模型连接与本地文件读写桥接。界面不得把预设选项冒充 AI 当场判断。

## 任意入口与可转换的创作路线

首页允许用户直接说想法，也提供“我现在只有……”的可选入口。这是识别**已有材料**，
不是让人提前挑一套永久不变的策划流程。

| 用户带来的材料 | 张翼的首个动作 |
|---|---|
| 喜欢的一款游戏 | 抽出最想保留的游玩瞬间，比较模组、学习性复刻与独立小样 |
| 一个玩法动作 | 写出第一回合和该动作的代价、结果 |
| 故事、世界观或题材 | 给两三种能让玩家亲手参与的方式 |
| 模糊愿望 | 给几个可比较的头十分钟体验，推荐轻量起点 |
| 已有企划、原型或玩家反馈 | 导入现状，从目前最大冲突或缺口继续 |

同一人可能同时带来参考游戏和故事，也可能先做模组，后来改做独立游戏。
入口可叠加，创作路线可转换，旧决定与转换原因留痕。完整独立游戏可以是长期目标，
第一次可玩交付仍压成短局。以后增加入口，只加识别规则和对应首轮动作，
不改项目记录与导出格式。

## 一屏应该有什么

1. **现在能玩成什么样**：用玩家动作展示当前短局；有可玩物时给打开入口。
2. **这一步要选什么**：初次草案之后进入页面内动态问卷，按主题集中展示当前适用的题；
   每题有 2–4 个通俗选项、后果和推荐理由，选择后即时更新依赖题。
3. **张翼改了什么**：原想法 → 本次建议 → 理由与代价；标明用户已拍板、张翼暂拟、
   已有原型证据或尚未验证。
4. **项目现在到哪**：已确定、待决定、待试玩三个短列表；可以回到旧决定并查看影响。

进度按关键不确定性消除与可玩物完成计，不按答题数或文档页数计。
专业术语放在可展开的“策划视图”；新手默认只看玩家体验语言。
动态问卷的题库、分支、预填、暂拟和立项书出口见
[动态问卷与立项生成方案.md](动态问卷与立项生成方案.md)。聊天里按轮询问可用于短会话，
不能成为工作台完整企划的唯一路径。

## 项目记录与文档出口

工作台需要一份**结构化项目记录**作为事实源，记录每项决定的 ID、来源、版本、
状态、依据、用户原话或选择、张翼建议、关联的小样与撤回历史。既有
`zhangyi.config.md` 和 `verdicts/` 应能导入并保留原文；新记录不能悄悄覆盖旧裁决。
文件名和字段格式在做第一条端到端样例时定稿；最小记录与导出约束见
[工作台状态与导出契约.md](../工作台状态与导出契约.md)。

文档由同一份记录生成，不各自维护独立事实：

| 导出物 | 给谁用 | 必含内容 |
|---|---|---|
| 项目总览 | 创作者与新接手者 | 想做什么、目前怎么玩、参考对象、路线、已定/暂定/待验证 |
| 阶段裁决书 | 设计复盘 | 过/缓/否、依据、风险、撤回与诚实声明，符合现有模板 |
| 可玩小样说明 | 开发者与测试者 | 运行方式、操作、结束/重开、这次验证的问题、已知缺口 |
| 开发交接包 | 下一个 AI 或开发者 | 项目状态、目标环境、文件地图、必须遵守的决定、未决事项、下一步验收 |
| 结构化记录 | 工具与模型 | 可解析的状态、决定 ID、文档版本与来源关系 |

导出前检查矛盾、缺失的胜负条件、未经用户拍板的方向性决定、未经运行的小样。
对不同大模型提供明确的接手指令和可核对的验收清单；不能保证模型天然遵从，
因此每次开发回传都要对照项目记录检查偏差。

## 第一批实现与验收

优先扩展现有离线 HTML“张翼之巢”，保留裁决书档案馆。首批界面接入五类开头，
深度实现先只做一条纵向样例：
“喜欢一款策略游戏 → 选择做独立短局 → 定一项关键胜负目标 → 展示介入记录 →
导出项目总览、交接文档和结构化记录”。可玩小样由宿主 AI 按项目记录生成并回挂，
界面不伪装成自带全品类游戏生成器。

验收时找一个未参与开发的玩家，从一句参考游戏感想开局：他不懂术语也能完成
一次路线选择、看懂张翼改变了什么、打开小样、导出交接包；另一模型读交接包后
能复述已定/暂定边界，并按验收清单做下一步。失败要记录原始操作与产物。

## 暂缓的投入

先不建设覆盖多品类、多引擎的通用代码库。每条样板都需要目标版本、启动方式、
可修改位置与真实运行记录；从真实任务中高频出现的品类开始加。首批界面若连
“玩家做选择 → 文档准确更新 → 下一模型接上”都没跑通，代码库扩容不会解决问题。
