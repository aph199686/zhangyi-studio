# 调研记录：银河恶魔城（genre.metroidvania）

- 检索日期：2026-09-28
- 检索执行者：AI 陪练（WorkBuddy 会话），非人工试玩
- 本包用途：**张翼通用品类包**（与任何具体项目无关），来源均为公开检索 + 卡片库蒸馏
- 结论一句话：银河恶魔城的最小闭环是「看见锁 → 拿到钥匙（新能力）→ 回溯开锁 → 世界变大」，成败全押在**地图（房间图）与能力门的耦合**上，而不是美术量或战斗手感。这是少数**必须先画完房间/能力图再动手做内容**的品类。

---

## 0. 划界（这个包吃什么、不吃什么）

**属于本包**：
- 2D（或可等效为分房间拓扑的 3D）横版/俯视探索；核心是**能力门控进度**（progression gated by mechanics）。
- 世界按**房间图**组织：多入口、枢纽、回路、捷径、可选隐藏。
- 玩家能力在流程中**改变移动/战斗方式**，并**追溯性地**打开已见过但当时过不去的空间。

**明确排除（避免与相邻包重叠）**：
- **纯线性横版平台跳跃**（关卡串行、无回溯、能力不改变拓扑）→ 不是本包。判据：「跳过后得到的只是带快速旅行的平台游戏」（Sorceress，2026）。
- **肉鸽/DBG 构筑**（局内随机构筑 + 永久成长）→ 已由 `genre.rogue` 承担。两者在「地图」上有交集，但肉鸽的核心是**构筑与局内随机性**，本包核心是**固定地图 + 能力门控**。**同一项目不要同时打这两个包**，否则首局骨架会打架。
- **战棋/管理**：各自已有包，不属本包。
- **纯解谜平台/机关解谜**：能力若不改变世界拓扑，只是解开单点的锁，属解谜包范畴（本包在来源中把「能力锁 vs 道具锁/谜题锁」明确对比过，见 §5-Q1）。

**边界声明（用于包数据 `boundary` 字段）**：
> 依据公开检索与卡片库蒸馏（2026-09-28），未运行、未试玩、未平衡、未做真实玩家测试。

## 1. 六个关键问题（先写在检索之前）

1. **玩家要什么**：玩家在这个品类里真正追求的是什么体验？什么会让老玩家立刻反感？
2. **第一小时**：开局第一个小时必须让玩家感受到什么、拿到什么，才算「入门了这个品类」？
3. **流派分叉**：这类游戏在做原型时通常会裂成哪 3–4 种路线？各自的第一局/首个区域目标是什么？
4. **新手真实死法**：新人做这个品类，最常见的失败方式是什么（不是「做得难看」，而是「做不下去/上线被骂」）？
5. **验收判据**：什么东西能证明「这个首局骨架是对的」？可被外部观察、不靠「我觉得好玩」。
6. **暂缓范围**：第一个原型**明确不做**什么？（用来防守范围失控）

## 5. 按六问蒸馏的判断

### Q1 玩家要什么

**要**：可被自己**发现**的空间；拿到能力后「世界向我打开」的扩张感；不靠地图也能记住路的清晰拓扑；探索有**独特回报**（新景象/角色/系统），而不只是收集品。
- 依据：A1（Team Cherry：「发现不是找到 500 面旗子，是遇到独特的景象、角色、系统」；「保留捷径，0.1% 玩家会做，但那感觉像是他们自己的发现」）；B6（「最好的关卡设计不需要地图」）；C4（「最喜欢的：探索」）。

**不要（会立刻反感）**：
1. **长距离 boss 回跑 / 尸体回收**——被反复点名，且被视为「无意义的难度填充」。
2. **地图不告诉你「本区还剩什么」**——收集党最恨。
3. **塞过多卡点**变成「puzzle platformer」或苦差。
4. **看不到任何门就卡住**（开局可达子图没触及第一个能力）。
- 依据：C1、C2、C3、C4；B4（「首次可达子图必须触到第一个能力所在房间」）。

### Q2 第一小时

**必须做到**：
1. **第一分钟就可玩且手感成型**——不要为了「展示成长」先把玩家削到不能跑不能跳。「核心循环从第一分钟起就应该是扎实的」；Ori、Hollow Knight、Axiom Verge 都没有限制基础能力。
2. **在前 5 分钟播种 1–2 个「看得见、打不开」的钩子**，并**尽快**给到第一把钥匙，让玩家亲手开一次锁，体验到「世界向我打开」。
3. **让第一个能力解锁 ≥2 处已见门**（否则这个能力的节拍被浪费）。
- 依据：B1（「开局不要把玩家弄得又累又烦」；反例：把跑步/跳跃/攻击都夺走）；B4（第一能力必须触达 + 每个能力 ≥2 门）；B5（《超银》前五分钟就展示「能力锁」：蓝门可用、桃红门不可用、小缝隙钻不进去）。

**交叉验证**：Q2 的「第一分钟可玩」有 B1（Bycer 2017）与 B2（Bycer 2014）两处独立表述，另由 A6（Ori 因手感被签下）佐证，≥2 独立来源 → 进默认建议。
Q2 的「每能力 ≥2 门」见 B4 与 B3（「钥匙要有多个锁」）两处独立表述 → 进默认建议。

### Q3 流派分叉（3–4 条路线）

原型期通常会裂成这几条，**每条的首个区域目标不同**：

| 路线 | 首个区域目标 | 代表 | 出处 |
|---|---|---|---|
| **能力门控探索（经典派）** | 一张地图 + 3–5 个改变移动的能力，靠「钩子 + 回溯」驱动 | Super Metroid、Hollow Knight、Haiku | B4、B5、A1、A3 |
| **战斗/RPG 成长派** | 在门控探索上叠数值/装备/等级，用成长弥补操作门槛 | Castlevania: SotN、Chasm | B2（月下），A2（Chasm 修战斗手感） |
| **氛围叙事派** | 世界氛围 + 情绪演出作为主卖点，探索为叙事服务 | Ori、一部份 Hollow Knight | A4、A5、A6、B6 |
| **紧凑短篇派（收束体量）** | 用很小的地图与很少的能力，把 5–8 小时做「密」而非做「大」 | Haiku the Robot（6 小时被评「无短板」）| A3 |

**暂缓的第五方向**：**程序化生成银河城**——多位开发者尝试后放弃或大幅回退（A1：Team Cherry 的「一两个小时迷你银河城、每次重排」方案被废弃：「It was a headache. It wasn't fun.」；B5 之外的 Aran Ink 自述亦记录「首次项目选这个 scope 是糟糕主意」）。**不进首局骨架，仅作备注。**

**交叉验证**：Q3 采用「四路线」有 A1/A3（经典/短篇）、B2+A2（成长派）、A4/A5/A6（氛围派）三组独立来源支撑，且「程序化」被明确排除有多处共识。

### Q4 新手真实死法

按「死在哪个环节」排序，均可被外部观察：

1. **地图/能力图没先画完就动手** → 每加一个能力都要推翻已有布局，反复重写。原文：「这是唯一一个设计文档必须先于代码完成的品类。」
2. **把升级做成「单点钥匙」** → 一个升级只在一个地方用一次，玩家只感觉「换了把钥匙」，不算体验成长。
3. **回跑/尸体回收设计失当** → 上线后被玩家点名「无意义填充」，churn 数据里 Design 问题占绝大多数。
4. **开局把玩家削得太狠 / 开局可达子图不触达第一个能力** → 玩家开局就卡住、看不到任何门。
5. **把「大」当成「好」** → 世界很大但空，物品与奖励节奏跟不上；玩家体感是「又长又空」。
- 依据：B4（1、4）、B1/B2（2）、C1/C2/C3（3）、C2（5：「world is huge but empty, very poor pacing of items and rewards」）。

### Q5 验收判据（可外部观察，不靠「我觉得好玩」）

**地图/能力结构层（可在设计文档上数出来）**：
- [ ] 房间图存在：每个房间列出「相连房间 + 该房间敌人」。
- [ ] 能力表存在：首个原型 **3–5 个能力**，每个能力写明「在哪个房间获得 + 解锁哪几道门」。
- [ ] **每个能力解锁 ≥2 个「玩家已见过但进不去」的房间**（硬判据）。
- [ ] 从入口（零能力）出发的可达子图**触及第一个能力所在房间**。
- [ ] 首个原型房间数有明确上限（参考 **12 房间**：1 入口 + 1 枢纽 + 3 群系 × 3 + 2 存档 + 1 boss）。
- [ ] 每个门在视觉上按能力类型区分（例：红裂缝=炸弹、蓝水拱=下潜、带灰高台=二段跳），玩家能下意识映射。

**体验层（试玩可观察行为，非感受）**：
- [ ] 玩家拿到第一个能力后，**主动**回到先前见过的某处（说明钩子生效）。
- [ ] 从存档点到最近 boss 的**单程穿越时间有上限**（避免长回跑；参考：不设快速旅行时把房间做小/把存档点放近）。
- [ ] 地图（若有）**能显示本区是否还有未取内容**。
- [ ] 任一时刻玩家**至少有 2–3 个**可探索方向（B2）。
- [ ] 存档/读取能完整恢复「已获得能力标志」，不只是位置。

**反例红线（触发即判负）**：
- ✗ 存在某个能力，其解锁的门 ≤1 个。
- ✗ 首个可玩块内 5 分钟看不到任何「看得见、打不开」的钩子。
- ✗ 强制回跑段单程超过约定上限，且无快速旅行/捷径兜底。
- 依据：B4（结构判据与红线）、B3（≥2 门）、B2（2–3 方向）、C1/C2/C4（回跑上限、地图显示未取内容）、A2（Mummy Demastered 把能力后移让回溯变爽点）。

### Q6 暂缓范围（第一个原型明确不做）

- ✗ **不做随机生成地图**（A1 明确废弃该方案；风险最高、收益最不确定）。
- ✗ **不做多结局/多路线分枝**（先证「单条主线 + 门控闭环」成立）。
- ✗ **不做数值/装备 RPG 系统**（B2：RPG 系统在银河城里是**可选**维度，不是品类前提）。
- ✗ **不做全量美术与配乐**（先用手感 + 灰盒房间验证结构；A6 证明当初签 Ori 靠的是手感不是画面）。
- ✗ **不做新机制实验（无先例的移动方式）**（A3：第一次做，把基础做对优先于做新东西；B4：先例能力集 = 二段跳/炸弹/冲刺/壁挂/下潜）。
- ✗ **不做大地图/多群系**（首个原型压在 12 房间级别）。
- ✗ **不做 meta 进度/永久成长**（那属局外长线，且与肉鸽包边界重叠）。

## 8. 没能回答的缺口

1. **「最优回跑时长上限」没有权威数字。** 玩家骂长回跑，但没人给出「单程不超过 X 秒」的可执行阈值。本包因此**只给方向与红线形态，不给具体秒数**。
2. **能力数量的上限**。3–5 是首个原型建议，但中大型作品的能力数/门数比例没有可靠来源。
3. **「钩子」密度**：单位区域内应布置几个看得见打不开的门，无来源。**保持为缺口。**
4. **快速旅行（bench-to-bench / 传送）何时该引入**，只有「大地图/回跑超 10 分钟才需要」这类**方向性**表述（B2），无量化标准。
5. **本包所有判断均来自公开检索与卡片库蒸馏，未经任何真实玩家试玩验证。** 任何「这局会好玩」的说法都超出证据范围。
6. **中文一手开发者访谈几乎缺失**：中文来源（B5）基于《超银》《月下》经典分析，未见近五年中国开发者的银河城一手复盘。属检索覆盖缺口，非「没有」。
