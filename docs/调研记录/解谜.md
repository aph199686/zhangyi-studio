# 调研记录：解谜（genre.puzzle）

- 检索日期：2026-09-28
- 检索执行者：AI 陪练（WorkBuddy 会话），非人工试玩
- 本包用途：**张翼通用品类包**（与任何具体项目无关），来源均为公开检索 + 卡片库蒸馏
- 结论一句话：解谜品类的产品**不是关卡，而是「理解崩塌」的那一刻**——玩家带着一个**合理但错误**的假设进入，用一个**几乎成功**的做法失败，撞上**一个拒绝合作的事实**，随后整套事实在**新框架**里同时变简单。设计要做的是把「误解」和「解法」**一样认真地设计出来**：错误假设必须是玩家**凭游戏教过的东西**自己形成的，从所见通向答案必须是**一条推理链而不是一次跳跃**。因此这个品类最硬的验收不是「玩家过关了没有」，而是「**玩家事后能不能解释为什么这样解**」；说「我就是一直乱试」的，等于关卡发了一把没有钥匙的锁。

## 0. 划界（这个包吃什么、不吃什么）

**属于本包**：
- **核心快感来自「我解开了」**——玩家卡住，然后不再卡住，如此反复数小时。这是本包与所有其它品类的分界线。
- 谜题的答案必须**可验证对错**：玩家能明确地「做对了」，且知道自己做对了（Scott Kim 定义：谜题是好玩的，且有正确答案）——不是沙盒式的「随便怎么玩都行」。
- 谜题承担**进度门**或**核心内容**：解开它才能推进、且解开它本身就是产品要卖的东西。
- 覆盖三个近邻形态：**推理型（deduction，有明确规则与唯一/可判定的答案）**、**洞察型（insight，靠重构认知而非穷举）**、**叙事/环境推理型（把线索藏在场景与信息里）**——三者在「公平性」与「验收」上共用同一套逻辑。

**明确排除（避免与相邻包重叠）**：
- **视觉小说／叙事冒险**（让读者一路读下去、在关键处做选择才是核心，谜题只是点缀）→ 已由 `genre.visual-novel` 承担。判据：**如果核心快感来自「我读到了、并且我选了」，那是视觉小说包；如果核心快感来自「我解开了」，那才是本包**。带解谜成分的叙事游戏（999/零逃脱类）落在两包交界，**同一项目只打一个包**，否则首局骨架会打架。
- **银河恶魔城**（能力门控探索 + 房间拓扑，锁是「能力」而非「理解」）→ 已由 `genre.metroidvania` 承担。判据：**能力锁是「我现在拿不到」；谜题锁是「我现在想不通」**。银河城里也有谜，但它的谜通常靠升级能过，而本包的谜必须靠想通才能过。
- **战棋 / 经营 / 棋牌 / 肉鸽构筑**：各自已有包。棋牌虽有「识破」，但那是先验博弈与概率，归棋牌包。
- **纯动作解谜（靠手速与精度）**：**本包不是动作品类**。若谜题主要靠像素级时机而非思考解开，那它是动作游戏而不是解谜游戏（见 Q5 反例红线：解谜不应考验视力与手速）。

## 1. 六个关键问题（先写在检索之前）

1. **玩家要什么**：解谜玩家在这个品类里真正追求的是什么体验？什么会让他立刻反感、骂「不公平」或直接退游？
2. **第一小时**：开局第一个小时必须让玩家感受到什么、学会什么，才算「入门了这个品类」？
3. **流派分叉**：这类游戏在做原型时通常会裂成哪 3–4 种结构路线？各自的第一章/首个目标是什么？
4. **新手真实死法**：新人做这个品类，最常见的失败方式是什么（不是「谜题太简单」，而是「做不下去/上线被骂不公平/没人愿意玩第二关」）？
5. **验收判据**：什么东西能证明「这个首局骨架是对的」？可被外部观察，不靠「我觉得这题很妙」。
6. **暂缓范围**：第一个原型**明确不做**什么？（用来防守范围失控）

### B. 分析视角（设计拆解，含方法论）

| # | 标题 | URL | 类型 | 一句话价值 |
|---|---|---|---|---|
| B1 | Puzzle Game Design: Engineering the Aha Moment（GameDesign.gg） | http://www.gamedesign.gg/articles/puzzle-game-design | 设计分析（本包最核心的机制拆解） | 提出**顿悟的四段结构**：**假设（合理但错误）→ 近乎成功 → 矛盾（一个事实拒绝合作）→ 重构（同一批事实突然都通了）**；**公平性检验**：「玩家在揭示之前有没有可能掌握所有必要的事实？」；**难度重定义**：「难的谜题不是零件更多的，而是错误框架更强、更诱人的」，**最好的谜题让显然的做法几乎成功**——带玩家走完大部分，在最后一步以**本身指向正解**的理由失败；**归纳检验**：最强的测试是「**玩家事后能不能解释为什么这样解**」，说「我就是一直乱试」= 发了一把没有钥匙的锁；**「错误的一步若能产生信息就保持推理，若什么都产生不了就把玩家推向随机试错，而品类就死在那里」**；**提示阶梯**：重述目标→指出相关元素→**点出值得怀疑的假设**→给第一步→最后才给完整解法，**最高价值的一级是「点出假设」**；提示必须**拉取而非推送**（闲置 90 秒就主动帮忙 = 宣布不信任玩家）；**产品是洞察不是关卡**——「用不同的顿悟数来数你的游戏，不是用房间数」；**程序生成的两条保证**：可解性（至少一解）+ 唯一性（多解则可靠猜），**没有求解器的生成器是 bug 工厂**。 |

## 5. 按六问蒸馏的判断

### Q1 玩家要什么

**要**：
1. **「我懂了」的那一刻**，而不是「我过关了」。这是品类的全部产品：B1 明说「用不同的顿悟数来数你的游戏，不是用房间数」；A1 把 Eureka 与 Fiero 区分开——**任何有挑战的游戏都能给 Fiero，只有谜题能给 Eureka**。顿悟甚至**不需要玩家自己解出**（看别人解、被剧透也能体验），这解释了为什么解谜内容能被「云」且主播观众也满足（A1）。
2. **公平**——答案必须**都在游戏里**、玩家**凭游戏教过的东西**就能想到。B2 开篇即「好谜题不在于巧妙，而在于公平」；B5「答案都在游戏里，准备充分与思考足够的话应该能一次通关，不要藏信息」。
3. **一次「几乎成功」的失败**作为正解的前奏——B1：最好的谜题让显然的做法**几乎成功**，带玩家走完大部分，在最后一步以**本身指向正解**的理由失败；B7 的「Liminal 想法」（教 90% 时间、最后 10% 靠打破规则解开）是同一件事的强化版。
4. **失败能产生信息，而不是死路**——B2「做错应该产生信息而不是死路；沉默是好谜题的敌人」；B1「产生不了信息的一步把玩家推向随机试错，而品类就死在那里」。
5. **深度但要可控**——B4 的元规则在 island.5 暗示、island.11 才首次必需；B6 的「规则简单、空间深邃」；C3「失败应是推理错误而不是误解规则」。

**不要（会立刻反感、骂不公平、退游）**：
1. **Moon logic（月亮逻辑）**——「现实生活中简单的问题被弄得没必要地复杂」，解法毫无道理（C1 的猫毛假胡子、Full Throttle 踢墙、橡皮鸭勾钥匙、花生酱）。这是**被点名最多、被写进品类讣告的设计**（C1）。
2. **像素狩猎（pixel hunting）**——关键物藏在整屏里的几个像素上，玩家只能拿鼠标一寸寸扫（C2、C1、B5、B7 四处独立点名）。
3. **猜动词 / 猜设计者的心（Designer 谜题）**——解法只有设计者想得通（C2、B5、B7：「本该在解谜游戏里的谜题」是同一类；另见 A2 的「Rabbit Trail」）。
4. **必须靠外部知识 / 无提示的特殊规则**——B5「答案都在游戏里」的反面；A2 的「不透明性」指「存在任何没有告知玩家的必要元素」。
5. **无反馈的重复**——Grim Fandango 要连续三次熄灭火海狸且毫无提示，玩家重复两次后会以为方法不对而放弃（C2）。
6. **惩罚失败 / 卡住**——错解就死亡或丢大量进度，玩家会变畏缩、停止实验（B7）；读到一半才发现需要很早以前才有机会拿的东西（C2 的 Leisure Suit Larry III）。
7. **把解谜挂在无关目标上**——为让飞船启动而弹对音符、为让桥出现而设定钟表（C2 的 Myst/Riven，「在设计上几乎说不通」）。
8. **一次「不诚实」的谜题毁掉全部信任**——Talos Principle 树上藏镜子后，玩家此后到处找树上藏的东西（A1、C5）。**信任是全局资产，一次破坏污染此后所有谜题。**

### Q2 第一小时

**必须做到**：
1. **教一条规则，且用「演示」而不是「讲解」**——A1「谜题每一关与其说是挑战不如说是教学」；B6「前几关不像谜题、像演示」；B3「设计脱不开教育」。第一小时必须让玩家**自己发现至少一条规则**，而不是读一段教程。
2. **让玩家经历一次完整的「假设→近乎成功→矛盾→重构」**——B1 的四段结构；第一小时若连一次完整的顿悟都没给，玩家不会相信后面的顿悟值得等。
3. **给一次「可被证伪的失败」**——玩家做错时得到**信息**而不是死路（B2、B1）。第一小时的关键不是不碰壁，而是**每次碰壁都学到东西**。
4. **建立信任**——让玩家相信「游戏是公平的、一定有解」（A1 的 Supraland NPC / Ittle Dew 告示牌）。第一小时要**明确承诺**：所需的一切都在你手边（B5「答案都在游戏里」；A1「你拥有解决所需的一切」）。
5. **给一切可尝试的手段，且重置/撤销要快**——B7「重置要快而无痛，否则玩家变得畏缩停止实验」；A2「让谜题易于尝试，降低试错成本」；B1 的提示应是**拉取而非推送**。
6. **第一小时的难度必须有「锯齿」而不是「坡道」**——B6「第四关考的和前三关不一样」；A4「不要迷信平滑曲线，引入新机制时给玩家喘息」；B1「难度是锯齿不是坡道：每引入新机制就把难度降下来，然后把这一个想法挖到穷尽再加下一个」。

**交叉验证**：
- 「教而不宣、前几关像演示」有 A1、B6、B3 三处独立表述 → 进默认建议。
- 「失败必须产生信息」有 B2 与 B1 两处独立、方向一致 → 进默认建议。
- 「重置要快、撤销要无损，否则玩家停止实验」有 B7、A2、B6（关于撤销的两派讨论）三处 → 进默认建议（但 B6 指出「限制撤销制造投入」也是一派，故本包把它标为**方法论共识，非唯一做法**）。
- 「难度是锯齿不是坡道」有 B1、B6、A4 三处独立 → 进默认建议。

### Q3 流派分叉（4 条结构路线）

原型期通常会裂成这几条，**每条的第一章/首个目标不同**：

| 路线 | 第一章 / 首个目标 | 代表 | 出处 |
|---|---|---|---|
| **纯机制链（mechanic-ladder）** | 一条规则 + 5–8 关「由易到难、每关只考这条规则的一个新面貌」的阶梯；零剧情也能立住 | Sokoban、Stephen's Sausage Roll、Baba Is You（单机制推导全作） | A2、A3、B6、C4 |
| **洞察型关卡集（insight-set）** | 每关一个独立的「啊哈」，关内不需长链推理；靠 **Liminal 想法**（最后 10% 打破前 90% 教的规则）制造最强顿悟 | The Witness、Portal 的后期关 | B1、B6、B7 |
| **推理/演绎（deduction）** | 有明确规则、靠排除与逻辑一步步收窄、**答案唯一可判定**；第一章先教「怎么记笔记/怎么标候选」 | 数独、Nonograms、Return of the Obra Dinn | A2（「让相关性与显著性相匹配」）、B1（唯一性保证）、B7 |
| **叙事/环境推理（narrative-inference）** | 线索散在世界里，玩家靠**观察+把信息拼起来**得出结论；第一章先教「观察什么、游戏会不会骗你」 | Return of the Obra Dinn、Her Story、Myst（但须避免 C2 的「无关逻辑谜」） | C2（好谜题清单）、B5、B1 |

**交叉验证**：四条路线的「第一关目标」都有独立来源支撑——「机制链靠阶梯」有 A2（流式/精华型谜题分类）与 B6（脚手架、Portal 第四关）两处；「洞察型靠 Liminal 想法」有 B1（错误框架要强）与 B7（打破 90% 规则）两处；「推理型靠先教记录法」有 B5（面包屑分级）与 A2（正向设计、唯一解）两处；「叙事推理靠不骗玩家」有 B5 与 C2 两处。

### Q4 新手真实死法

按「死在哪个环节」排序，均可被外部观察：

1. **把「误解」当成玩家自己想出来的**——设计者太清楚答案，忘了玩家**凭什么**能形成正确的假设。B1 明确：「设计工作是把误解和解法一样认真地设计出来」；A4 亲历「自以为巧妙的一关被朋友用完全没想到的方式解开」；A3 的「人极易对非预期解视而不见」是同一根因。**这是本包最核心的死法。**
2. **靠「猜设计者的心」/不透明规则**——C2（猜动词、过度引导）、B5（Designer 谜题）、A2（不透明性的六大问题）、B7（「猜设计者的心」）。玩家的下场是**乱试**，而 B1 说乱试就是品类死掉的地方。
3. **像素狩猎 / 线索显著性失衡**——C1、C2、B5、B7 四处。A2 的正解是「**让相关性与显著性相匹配**」。
4. **一次不公平的谜题毁掉全局信任**——Talos Principle 树上镜子（A1、C5）；C1 的 moon logic 让整个品类「锈死」。
5. **难度曲线做成坡道而不是锯齿**——B1（锯齿）、B6（第四关不同）、A4（别迷信平滑曲线）、B7（突然难度飙升是反模式）。
6. **不测试 / 只测「预期解」**——A3（非预期解靠外人才发现）、A4（要自己「作弊」找捷径）、C3（观察行为而非听意见）；C2「充分测试：玩家能合理尝试的任何行动都该有合理回应」。
7. **状态空间/瓶颈失控**——A5：状态空间越大、瓶颈越难（甚至多瓶颈），难度只会爆掉，玩家在长链上有一个点卡死就全盘崩。

### Q5 验收判据（可外部观察，不靠「我觉得这题妙」）

**结构层（可在设计文档 / 关卡清单上数出来）**：
- [ ] **每关写明「考验什么」**：观察 / 逻辑 / 模式识别 / 协作 / 耐心，并且**不知道考什么的关卡一律砍掉**（B2 第一原则）。
- [ ] **每关写明「错误框架是什么」**：玩家第一反应会形成一个**合理但错误**的假设，且这个假设是**游戏教过的东西**导出的（B1）。
- [ ] **每关写明「矛盾点是什么」**：哪一个可观察的事实会**拒绝合作**，逼玩家换框架（B1 四段结构）。
- [ ] **公平性检验逐关过一遍**：「**玩家在揭示之前有没有可能掌握所有必要的事实**？」（B1 原文的 fairness test）；答案是否**都在游戏里**（B5）。
- [ ] **每关必须有「确认线索」**，让玩家知道自己走在对的路上（B8 的确认线索；A2「让玩家知道自己在做对的事」）。
- [ ] **红鲱鱼数量受限且有用途**：每个元素要么有用途要么明确是装饰；**如果所有东西看起来同样重要就没有东西显得重要**（B7、B8、B5）。
- [ ] **不依赖任何外部知识**：所有需要的规则/事实都能在游戏内取得（B5、B7）。
- [ ] **提示阶梯已设计**：重述目标 → 指向相关元素 → **点出值得怀疑的假设** → 第一步 → 完整解法；**提示必须是拉取而非推送**（B1）。
- [ ] **重置/撤销要快，失败不惩罚**（B7、A2、B6）。

**体验层（试玩可观察行为，非感受）**：
- [ ] **归纳检验（本包最强判据）**：玩家解完后**能解释「为什么这样解」**；说「我就是一直乱试」= **判负**（B1）。
- [ ] **玩家在某关的停顿/回头/放弃点被记录下来**；若放弃集中在同一关，说明**要么不公平、要么显著性失衡**（C3 的行为观察法）。
- [ ] **玩家的口头语言里出现「原来是这样」而不是「居然还可以这样」**——前者是 Eureka，后者是「O Really?」（A1 引黄卫华）。
- [ ] **玩家不用看攻略就能过**（C2 的「答案都在游戏里」）；若开发中的测试者反复要攻略，说明线索/假设没有立住。
- [ ] 每条存在的主张都有至少 **2 个独立来源**（本调研纪律，非品类判据）。

**反例红线（触发即判负）**：
- ✗ 存在一关的解法**需要游戏里从未教过的规则**（B2、B5、B7）。
- ✗ 关键交互物**无法从背景中区分**（像素狩猎，C1/C2/B5/B7 四处）。
- ✗ 玩家做错后**得不到任何信息**（B2、B1，且 C2 的 Grim Fandango 案例）。
- ✗ **同一个事实被用两种不一致的方式解释**（Talos Principle 式破坏信任，A1、C5）。
- ✗ 一关存在**两条不同思路都能解**且设计者没有把它们当特性（唯一性失守，B1、A3）。
- ✗ 有玩家**需要长期乱试才能过**的关卡（B1「品类死在那里」、B7「开始乱试说明太难或目标不清」）。
- 依据：B1（四段结构 + 公平性检验 + 归纳检验 + 唯一性）、B2（先定考验什么 + 失败产生信息）、B5（答案都在游戏里）、B7（反模式表）、C1/C2（moon logic / 像素狩猎 / 无反馈重复）、A1（信任）、A3（非预期解）、A5（状态空间瓶颈）。

### Q6 暂缓范围（第一个原型明确不做）

- ✗ **不做程序生成 + 求解器**（B1：「没有求解器的生成器是 bug 工厂」，且可解性 + 唯一性两条保证都不免费；首版全部手工造关）。
- ✗ **不做非线性大地图 / 开放式关卡选择**（先证「一条线性能被读懂」，B6 的脚手架逻辑）。
- ✗ **不做多机制堆叠**（B6「规则简单、空间深邃」；先证一条规则能长出 5–8 个不同面貌，再谈第二条）。
- ✗ **不做全量剧情/演出**（解谜的顿悟不依赖剧情；C4 的 Stephen's Sausage Roll 与 A3 的 Baba Is You 都是几乎零剧情的成作）。
- ✗ **不做全量美术与定制动画**（先用最简单、可读的图形验证「规则能不能被读懂」；B8「如果所有东西看起来同样重要就没有东西显得重要」，先靠形状/颜色/对比而非精度）。
- ✗ **不做关卡编辑器与 UGC**（属局外系统与生产力工具，先证局内闭环）。
- ✗ **不做局外长线（成就、多层进度解锁、每日挑战）**（属局外系统，先扩局内体量）。
- ✗ **不做考验手速/精度的关卡**（B5、A4：解谜应以智力为主，快速反应与极端精度不属于解谜游戏）。
- ✗ **不做需要外部知识（真实世界知识、冷门文化）的谜题**（B5、B7；可被查证 = 玩家会去搜而不是想）。
- ✗ **不做「一次不诚实」的谜题**（A1、C5：信任是全局资产，第一版就用统一规则贯穿全部关卡）。

- **「多少关才够」** → **无权威数字**，保持为缺口。

## 8. 没能回答的缺口

1. **「每关的难度应该如何量化」没有权威数字。** A5 用状态空间图讨论推箱子，B1 用「错误框架的强度」讨论，两者视角不同、无法互换；本包因此**只给「难度是锯齿」「错误框架要强」这类方向，不给数值**。
2. **「唯一解 vs 多解」的界在哪。** B1 说多解在推理型谜题里是「坏的」（可被猜），B2 说「避免唯一解设计」以免变成被推着走，B7 说「尊重玩家自己的逻辑，若无世界内讲得通就该让它成立」——三者张力未消解。本包因此只要求「**把非预期解当成一个要处理的对象**」（要么封掉、要么当特性），**不给「必须唯一解」的硬线**。
3. **「为什么 P 站/某类解谜游戏近年更火」等市场层判断**没有拿到来源，属于**检索覆盖缺口**。
4. **中文一手开发者复盘偏少**：A2、B3、B4 均为中文笔记/分析（转述 GDC 或拆解机制），但**没有一篇中文的「我做完一款解谜游戏后复盘」的一手文**。属检索覆盖缺口，非「没有」。
5. **本包所有判断均来自公开检索与卡片库蒸馏，未经任何真实玩家试玩验证。** 任何「这一关会让玩家恍然大悟」的说法都超出证据范围。
6. **「演出/音效/动画反馈」的量级**在本次检索中**没有拿到可引用的权威来源**（B1 提到提示系统、B8 提到还原线索，但没有参数）；因此本包 `verification` 只给「失败要有反馈、确认线索要可感知」的方向，**不给具体演出参数**。
7. **同人/独立团队的解谜项目死亡率与常见中止原因**没有数据来源；C4 是唯一一款成品的玩家视角，不足以支撑统计性结论。
