# 调研记录：视觉小说 / 叙事冒险（genre.visual-novel）

- 检索日期：2026-09-28
- 检索执行者：AI 陪练（WorkBuddy 会话），非人工试玩
- 本包用途：**张翼通用品类包**（与任何具体项目无关），来源均为公开检索 + 卡片库蒸馏
- 结论一句话：视觉小说／叙事冒险的最小闭环是「读者愿意一路读下去 → 在关键处做出一个『我自己的』决定 → 走到一个**有收束感**的结局」，成败全押在**文本本身的推进力（声音、悬念、节奏）与选择的意义感**上，而不是美术量、配音量或分支数量。这是少数**必须先决定结构形态（主干/分支/多线）再写字**的品类——但结构复杂度必须与产能严格挂钩。

## 0. 划界（这个包吃什么、不吃什么）

**属于本包**：
- **以阅读/文本推进为主**，玩家输入以「对话选择 / 时机选择 / 少量交互」为主，不依赖操作技巧。
- 叙事是核心价值，玩法（若有）服务于叙事，而非相反。
- 结构上必须存在**作者设计的叙事弧**：可以是单线（kinetic）、主干+短枝、多线（hub-and-spoke）、或多线解谜（multi-route mystery）。
- 覆盖两个近邻形态：**纯视觉小说（VN）** 与 **叙事冒险（interactive story / Telltale 式）**——两者在本包内共用同一套验收逻辑，差异只在「单次选择是否带操作/探索成分」。

**明确排除（避免与相邻包重叠）**：
- **解谜**（谜题本身是核心挑战、解开谜题是进度门）→ 已由 `genre.puzzle` 承担。判据：**如果玩家的核心快感来自「我解开了」，那是解谜包；如果核心快感来自「我读到了、并且我选了」，那才是本包**。带解谜成分的叙事游戏（999/零逃脱类）落在两包交界，**同一项目只打一个包**，否则首局骨架会打架。
- **银河恶魔城**（能力门控探索 + 房间拓扑）→ 已由 `genre.metroidvania` 承担。带叙事的银河城不属本包。
- **战棋 / 经营 / 肉鸽构筑**：各自已有包。
- **纯文字冒险（parser / 无选择的纯阅读小说）**：如果是**完全无选择**的纯阅读，且无任何交互，则不构成本包的最小闭环（本包的 Q2 要求「至少一次玩家自己的决定」）；请先补一个选择点再回来打本包。

**边界声明（用于包数据 `boundary` 字段）**：

## 1. 六个关键问题（先写在检索之前）

1. **玩家要什么**：读者在这个品类里真正追求的是什么体验？什么会让老读者立刻反感/弃读？
2. **第一小时**：开局第一个小时必须让读者感受到什么、拿到什么，才算「入门了这个品类」？
3. **流派分叉**：这类游戏在做原型时通常会裂成哪 3–4 种结构路线？各自的第一章/首个目标是什么？
4. **新手真实死法**：新人做这个品类，最常见的失败方式是什么（不是「写得难看」，而是「做不下去/上线被骂/没人读完」）？
5. **验收判据**：什么东西能证明「这个首局骨架是对的」？可被外部观察、不靠「我觉得感人」。
6. **暂缓范围**：第一个原型**明确不做**什么？（用来防守范围失控）

## 5. 按六问蒸馏的判断

### Q1 玩家要什么

**要**：
1. **一个值得花时间的叙事声音**——开篇数小时内靠「设定悬念 / 主角声音 / 人物化学反应 / 独特氛围」抓住人（B5）。
2. **「我的选择被记住」的感觉**，而不一定是「我的选择改变了结局」。玩家真正在意的三件事（分析归纳）：即时反馈（游戏有没有承认我的选择）、角色反应（NPC 是否因我做了什么而对我不同）、情绪回报（我的选择被肯定或被挑战得有意思）（B3、B2）。
3. **一次通读就能拿到一个完整故事**——被明确诉求（B7 结论段）。
4. **有收束感的结局**：坏结局也应是「另一个结局」，不是惩罚（B3 引 Finley 关于失败应提供收束）。

**不要（会立刻反感/弃读）**：
1. **「不归路分叉」**——数小时前一个看似无关的小选择，无声地决定你的结局，且不给任何提示。**这是被点名最多、最被记恨的设计**（C3、C4、B7）。
2. **攻略依赖度拉满的随机选择**：一周目根本无法预判结果，必须开着攻略玩（C2「Hatsukoi：必须用攻略」）。
3. **坏结局过密且像 Game Over**：「不到半小时撞两个结局，且未必与剧情相关」（C2）。
4. **「找触发点」铁轨**：看似能自由行动，实则必须撞到唯一正确的剧情点才推进（B7：Hotel Dusk）。
5. **空白主角**：在 VN 里「故事就是玩法」，空白主角会把所有戏剧张力推给配角（B7）。
6. **有分支但不给即时反馈/角色反应**：玩家会察觉自己在「假装玩」（B2）。

### Q2 第一小时

**必须做到**：
1. **第一个可读块内确立「主角声音 + 一个具体的人物关系」**——不是世界观说明书。B5：开篇决定是否继续，靠的是「设定悬念 / 主角声音 / 人物化学反应 / 独特氛围」的组合，而不是铺垫量。
2. **在第一小时内给出至少一个「选择被承认」的实例**——选完立刻有可感知的反应（一句话、一个表情、一段后续）。B2/B3：这才是意义感的来源；反之即「假装玩」。
3. **把玩家带过「至少一个选择点」并抵达一个**明确的路标（章节/线/小高潮）**再判断是否入门**。依据：B6——VN 天生前置铺垫，且**最有力的内容常被安排在「线/弧」的边界上**，「在弧中间退出等于在评判一个不完整的段落」；A1 的 30–45 分钟起量正好覆盖「序章 + 一个选择点 + 一个章节标」。
4. **不把「慢」当默认美德**：慢必须有**可辨识的功能**——铺氛围、加深关系、埋后续要用的细节（B5）；「作者写得爽」的慢几分钟内就会被读出来（B5、B6）。

**交叉验证**：「选择必须有可感知的即时反馈/角色反应」有 B2（Frictional/Gamasutra，心智模型）与 B3（学术论文 + 玩家在意三件事）两处独立表述 → 进默认建议。
「第一小时应该走到一个线/弧边界再判断」有 B6（明确建议读过一个自然的弧边界）与 C1（名作的分章节点普遍在数小时而非开头）两处独立佐证 → 进默认建议。
「慢要有功能、否则是填充」有 B5 与 B6 两处独立表述 → 进默认建议。

### Q3 流派分叉（4 条结构路线）

原型期通常会裂成这几条，**每条的第一章/首个目标不同**：

| 路线 | 第一章 / 首个目标 | 代表 | 出处 |
|---|---|---|---|
| **单线（kinetic）** | 一篇约 5000 词、15–25 分钟、**一个结局**的完整短篇；零分支，全部心力在文本质量与演出节奏 | Ren'Py 首作档案例（1507 词 / 只一个结局）；「对首次作者通常最明智」（B4） | A1、B4、B1 |
| **主干 + 短枝（beads on a string）** | 一条必读主干 + 2–3 个「记住我做过什么」的短枝；选择多半**汇流**，靠即时反馈与角色反应兑现意义 | 80 Days（内容灵活适配处境）、Pentiment 的主题型选择 | B3、B1、A2、A5 |
| **多线（hub-and-spoke）** | 共通线（介绍全部角色/世界/语调）+ 分支点 + 各角色线；共通线写足，因为它是**每个读者都会看到的内容** | Clannad、Little Busters、Key 系 | B4、B5、C1 |
| **多线解谜（multi-route mystery）** | 每条线各给一块拼图，**集齐才能开真结局**；结构最复杂，必须先写完整结构图 | Zero Escape / 999、Umineko | B4、C3 |

**交叉验证**：四条路线中，「单线最明智」有 A1（官方教程直接建议新手做小做简）与 B4（明确写「对首次作者，kinetic 往往是最明智的选择」）两处独立来源；「主干+短枝是低产能标准解」有 B1（成本乘数表 + Remember/Restrict 优先级）与 B3（beads on a string）两处独立来源；「多线共通线是最重要的一块」有 B4 与 B5 两处；「多线解谜最复杂」有 B4 与 C3（999 的隐藏前置）两处。

### Q4 新手真实死法

按「死在哪个环节」排序，均可被外部观察：

1. **scope 失控 / scope creep** → 项目做不完。这是被点名最多的死法：「项目没做完的主因就是太大太雄心」（A1）；「延期的第一主因」与「造成的废弃项目比任何引擎 bug 都多」（C6、C7）。
2. **先在纸上没定结构就动笔** → 每加一条线/一个选择点都要回头改已写内容，成本指数级上升（B4「动笔前先产出完整结构文档」；C6「最常见的保护措施是动笔前写完设计文档」）。
3. **选择与后果脱钩或无反馈** → 玩家察觉「假装玩」（B2），或撞上「不归路分叉」被记恨（C3、C4）。
4. **开局把最好的内容留太靠后 / 序章写十二遍** → 「如果你的最佳场景在第八小时，几乎没人会看到」（B1）；「因为序章平庸而弃坑的人，远少于因为永远到不了第二章而弃坑的人」（B1）。
5. **测试被低估** → 只走「好结局」一条路，替代结局里藏着坏场景/断裂（C6、A6 的反面）。
6. **美术/技术债把项目拖垮** → 把「其实已经不是 VN」的设想硬塞进引擎，或做到一半换引擎（C5：六个月 crunch、两个月原型作废）。

### Q5 验收判据（可外部观察，不靠「我觉得感人」）

**结构层（可在设计文档上数出来）**：
- [ ] **存在一份完整结构文档**：列出每条线、每个主选择点、**每条线的词数目标**、线之间的关系（B4 铁律）。
- [ ] **词数可估算**：用样章词数 × 场景数得出总词数区间；首个原型**有明确词数上限**（A1 建议 5000 词 / 30–45 分钟；A7 建议 1–2 万字 / 2–3 小时；两者取其一即可，但必须写明是哪一个）。
- [ ] **每个选择点都写明「它改变了什么」**，且改变类型被标注为三者之一：`Branch`（换路，最贵）/ `Restrict`（开门条件，便宜）/ `Remember`（角色后续提及，最便宜、印象最深）（B1）。
- [ ] **选择类型配比检查**：`Remember` 与 `Restrict` 的数量应**不少于** `Branch`（B1：「新手分支太多、记住太少」）。
- [ ] **不存在「不归路分叉」**：任何会导致路线锁定/坏结局的选择，必须在**选择当刻或紧随其后**给出可辨识的提示（C3、C4、B2）。
- [ ] **坏结局有收束内容**，不是戛然而止的 Game Over（C2、B3）。

**体验层（试玩可观察行为，非感受）**：
- [ ] **首次试读者的弃读点位置被记录下来**；若弃读点集中在开篇 X 分钟内，说明「主角声音/人物关系/氛围」其中之一没立住（B5、B6）。
- [ ] **读者在做出选择后能自发说出「游戏记住了我做的什么」**——若说不出，说明缺即时反馈与角色反应（B2、B3）。
- [ ] **读者能说出「这一个决定是我的」**（而非「这游戏要我这么做」）。
- [ ] **走到一个结局后，读者能复述主线发生了什么**（收束感成立）。
- [ ] 每条存在的主张都有至少 **2 个独立来源**（本调研纪律，非品类判据）。

**反例红线（触发即判负）**：
- ✗ 存在一个会改变结局的选择，且在选择时玩家**不可能**知道它重要（C3、C4）。
- ✗ 首个可玩块读完，读者说不出任何一个人物的具体特质（B5、A4）。
- ✗ 分支数 > 6 而 `Remember` 类反馈 = 0（B1 的配比失衡）。
- ✗ 只测试了「好结局」这一条路径（C6、A6 的反面）。
- ✗ 结构文档缺失，或文档里没有每条线的词数目标（B4）。
- 依据：B1（配比）、B2/B3（反馈与意义）、B4（结构文档）、C2/C3/C4（不归路红线）、C6（测试）、A1/A7（量级）、A4（人物具体性）。

### Q6 暂缓范围（第一个原型明确不做）

- ✗ **不做全配音**（A1 的四个首作案里三个都没有音乐或只有网络音乐；配音是「关键场景可选」级别，非前提）。
- ✗ **不做多线解谜（multi-route mystery）结构**（B4：结构最复杂、最需要前置规划；先证「单线/主干+短枝」能立住）。
- ✗ **不做全量美术**（先用手势化的立绘占位 + 少量背景验证文本与结构；A6「合并角色」证明省立绘是可行手法）。
- ✗ **不做「自由行动找触发点」式叙事冒险**（B7：是「铁轨」的主要来源；若要做，必须先在纸面证明有多个合法推进路径）。
- ✗ **不做分支数量 > 3 的主线分叉**（B1 成本乘数；先证「少分支 + 多一点 Remember」的配比成立）。
- ✗ **不做局外长线/多周目解锁系统**（属局外系统，先扩局内体量）。
- ✗ **不做「空白主角」**（B7；本包要求主角至少有一个明确的声音与立场）。
- ✗ **不做跨作品/联动的资源复用**（先把一个独立短篇做完）。

## 7. 证据强度自评

**总评：充分（对「结构层 / 写作纪律」判断）／有限（对「产能数字」判断）／单薄（对「市场与口味层」判断）**

| 被判断的字段 | 强度 | 依据 |

## 8. 没能回答的缺口

1. **「最优分支数量」与「最优词数」没有权威数字。** A1 说 5000 词，A7 说 1–2 万字，C6/C7 说中型是 13–20 万词。本包因此**只给量级区间与「必须写明上限」的纪律，不给唯一数字**。
2. **「选择幻觉」的边界：什么程度的重汇流是可接受的。** B2 说「玩家会察觉」，B1 说「通向同一结果也能成立，只要强化主题」——两者张力未消解。本包因此要求「意义靠即时反馈/角色反应兑现」，作为可观察的折中判据，但**没有可靠的量化边界**。
3. **多线/多周目的解锁顺序**（先走哪条线、真结局何时开放）只有「必须集齐拼图」这类方向性表述（B4、C3），无标准做法。
4. **中文一手开发者访谈缺失**：仅有 A7 一份中文开发指南（且为教程性质）。属检索覆盖缺口，非「没有」。
5. **本包所有判断均来自公开检索与卡片库蒸馏，未经任何真实读者/玩家试玩验证。** 任何「这个故事会感人」的说法都超出证据范围。
6. **「演出/演出节奏」的量级**（每屏几句、停留多久、何时静默）在本次检索中**没有拿到可引用的权威来源**，因此本包的 `verification` 字段不给具体演出参数，只给「演出要有功能，不能只是描述」的方向。
