# 张翼 · Spread the Pinions

> 你只有一个人。但你可以张开翅膀。

张翼是一套装进 AI 助手的**游戏设计陪练 skill**。你给它一句想法、一个做不做的纠结，或一版已有方案；它先给可修改的设计草案，再指出真正会影响玩家体验的取舍，陪你用小样和真人反馈检验。你拍板，它负责把判断、理由和未验证的风险留成档案。

**第一次使用？**在项目文件夹双击 [`启动张翼工作台.bat`](启动张翼工作台.bat)，保持弹出的命令窗口打开。需要已安装 Node.js。先看[产品说明书](docs/产品说明书.md)：一页了解工作台、张翼 skill、项目包与后续接力。

它可以替你**提出候选点子**，也能在方向清楚后做一个可试玩的小版本：让你先玩，再决定值不值得继续做。它不会把候选当成你的决定，也不会仅凭纸面方案或自己生成的原型宣称游戏“好玩”。

## 第一次使用，你会得到什么

你只要说：**“我想做一个开猫咪咖啡馆的游戏。”** 不用先懂“核心循环”“设计支柱”这些词。张翼应该先交一页能反应的草案：

| 你交给张翼 | 张翼替你推进 | 你能看见的变化 |
|---|---|---|
| “开猫咪咖啡馆”一句话 | 写出玩家头十分钟：接第一位客人、安排猫与座位、处理猫不愿接客的意外 | 从题材变成玩家真的能做的事 |
| 想同时做装修、繁育、外卖、社交 | 建议首版只保留“猫与客人的匹配”，其余先砍，并说明每项会挤掉什么 | 范围变小，游戏最特别的部分变清楚 |
| “这样会不会好玩？” | 指定最小可玩小样：三只性格不同的猫、三位需求冲突的客人；找陌生人玩，看他们是否愿意为自己的安排负责 | 把空泛的担心变成可以观察的问题 |

这页草案不是替你定案。你说“我最想做装修”，张翼就应重新设计围绕装修的玩法，并说明保留它的成本。它的价值在**做出有理由的判断，然后接受你的纠正**，不是在回答里宣布“我使用了某个 skill”。

## 你可以在什么时候找张翼

| 你眼下的难题 | 可以直接这样说 | 张翼应交给你什么 |
|---|---|---|
| 只有模糊点子 | “我想做一个……，帮我落地。” | 头十分钟怎么玩、亮点、先砍什么、下一步 |
| 喜欢一款现成游戏 | “我玩了《文明6》，想做五代十国版本。” | 分清模组、独立小样与完整游戏；先重现最喜欢的一段体验，不要求先有创新点 |
| 想尽快玩到灵感 | “我选这个方向，别讲术语了，做个能玩的最小版本。” | 可打开、能操作、有结果和重开入口的小样；说明它在试什么 |
| 想加一个功能 | “我想加联机/抽卡/第二套战斗，值不值？” | 它解决的问题、代价、过/缓/否的判断 |
| 故事和玩法分家 | “这段剧情和玩家操作怎么连起来？” | 角色想要什么、玩家的选择改变什么、输赢后故事怎么动 |
| 数值看着不对 | “这套经济/胜率会不会把玩家卡死？” | 先写清假设，再做模拟；指出模型能和不能证明什么 |
| 有可玩小样 | “找几个人试玩，应该看什么？” | 试玩任务、观察点、记录方式和基于样本的结论 |
| 要发售或隔天继续 | “现在能发吗？”/“帮我接着上次做。” | 有证据的检查结论 / 能接上进度的交接档案 |

不确定该走哪一步，直接把当前想法和最烦的一件事告诉它。张翼应先给草案，不把入门变成填表。

## 为什么是"张翼"

市面上的 AI 游戏工具都在解决"产能"。张翼解决的是"判断"。

- **它会裁决**：每次评审必落裁决（过 / 缓 / 否），没有"两个都有道理"。
- **它会诚实**：每次输出末尾带诚实声明——本次能证明什么、不能证明什么。
- **它会撤回**：新证据出现时，它公开撤回自己之前的结论，并记录为什么。
- **它会记账**：被否决的事项进否决清单，想复活？拿新证据来。
- **它会留档**：每次评审产出一份裁决书，存在你自己的项目仓库里，攒成你项目的档案。

用过张翼的项目，会留下别人一眼认出的东西。

## 三层形态

```
第一层 · 本体    标准 Agent Skills（本仓库），住进你已有的 AI 助手
第二层 · 巢      张翼之巢：本地 HTML，裁决书档案馆已上线，羽翼成长图规划中
第三层 · 印记    裁决书：每次使用在你项目里留下的带编号档案，即品牌的传播体
```

### 张翼之巢 · 裁决书档案馆（已上线）

双击打开 `nest/index.html`（零依赖、离线可用），把项目 `verdicts/` 目录里的
裁决书拖进去——渲染成带朱砂印章的正式文书：过是红圆章、缓是蓝签收章、
否是红方章、装饰是虚线作废戳。支持打开整个 verdicts 目录逐份翻阅（Chromium），
Ctrl+P 可直接打印存档。

### 张翼工作台 · 立项、审方案与做出来

双击仓库根目录的 [`启动张翼工作台.bat`](启动张翼工作台.bat)，它会启动本地服务、选择可用端口并打开页面；关闭弹出的命令窗口会停止服务。进入页面可先选项目文件夹；点“保存项目包”会直接把 ZIP 写进该目录，同版本已有文件时自动使用新文件名，不覆盖旧包。当前内置浏览器没有直接写本地目录的接口，所以这一步由仅在本机监听的服务完成；也可粘贴目录路径或使用“浏览器下载”。直接打开 [`nest/studio.html`](nest/studio.html) 仍可离线答题，但不能直接存入指定文件夹。

从一款喜欢的游戏、一个玩法点、故事、模糊愿望或现有项目进入；入口可以多选。游戏品类独立于是否有现成工程。已有项目可导入 `zhangyi.project.json` 接着做，已确认的题不重问。记录起步路线和第一份作品重点后，页面会显示适用的选择题；可集中作答、回改、展开可选题，并查看《立项书草案》。第二页“审方案”会显示已定骨架、已知矛盾、制作风险与需要玩家拍板的选择；也能把项目包交给带张翼 skill 的 AI 审查，再把结构化结果导回页面，逐条采纳或暂缓。第三页“做出来”把已审方案整理成《制作任务包》交给自己的 AI 或开发者，做出后把构建、运行、玩通、真人试玩四级可玩证据导回页面，证据状态板只随证据升级；方案改动后旧证据标为需复核。工作台在浏览器本地保存当前记录，第四页“试玩与修订”按证据状态导出《试飞任务》（首次观察/体验走查/修订核对三档），执行后导入场次级试玩记录（缺样本三要素降级为自述级），再生成《修订建议》回前两页拍板。导出的 ZIP 包含项目记录、项目总览、开发交接、立项书草案、方案审查记录、张翼审查任务、张翼介入记录、制作任务包和试飞任务，共九份同源文件。

当前 44 题题库与推荐均为**明确标注的离线规则**；部分推荐会根据已有决定变化，发现明确矛盾时会提示复核，但尚不能代替张翼的完整专业评审。立项书草案仍是已确认/暂拟/未定的结构化汇总。页面尚未直接调用张翼 skill 生成完整立项书或可玩小样。把导出的交接文档给 AI 助手继续推进即可。修改页面或[产品说明书](docs/产品说明书.md)后运行 `node tools/build_studio.mjs`，同步生成离线脚本包与 `nest/guide.html`。

## 安装

把 `skills/` 下你需要的 skill 目录（共 9 个）复制到你的 agent 的 skills 目录：

- Kimi Code：`C:\Users\<你>\.agents\skills\`
- Claude Code：`~/.claude/skills/`

然后在你的游戏项目里对 AI 说一句“我想做个游戏”或直接讲你的点子。先看它给出的草案，再纠正不符合你想法的地方。

## 授翼仪式

第一次在你的项目里启用张翼时，它先给能玩起来的概念草案；你纠正后，它才把已确定的项目方向写入配置与第一份裁决书。只问“张翼能做什么”时，不创建项目文件。
