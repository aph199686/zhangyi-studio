# 阶段识别表（zhangyi 路由依据）

张翼按工作阶段组织。路由的关键是**用户此刻在干什么**，不是"这个问题属于哪个学科"。
拿不准时按现有材料先给最接近的草案或诊断，并说明暂定依据。

## 触发信号明细

### → zhangyi 总入口（使用说明）

- “张翼是什么 / 能帮我什么 / 怎么用 / 适合新手吗”
- 给具体帮助范围、一个微型示例和一句可复制开场话；这是产品咨询，
  不启动授翼、不创建文件、不要求用户先提供项目资料。

### → zhangyi-kickoff（立项立意）

- "我想做个游戏 / 我有个点子 / 我想做独立游戏"
- “我想做游戏但没想好做什么 / 我只想好一个怎么玩的点”
- "做什么题材好 / 这个方向行不行 / 帮我看看这个创意"
- "核心玩法 / 核心循环 / 游戏支柱 / design pillar"
- "竞品分析 / 参考游戏 / 这个游戏哪里值得学"
- "这个玩法要不要加 / 这个功能做不做"（立项期的取舍）
- 用户带着企划或原型想重新确定**整体方向**时也可进入；先读现状，不重走零点子入口

### → zhangyi-relay（接力）

- "接着上次 / 上次说到 / 我们继续"（新会话续接）
- "新会话 / 换个窗口继续 / 交接一下"
- "项目现在什么状态 / 帮我同步进度"
- "帮我写个接续提示词 / 下次怎么接"
- 每批工作收尾时**主动触发**：提醒用户落交接段

### → zhangyi-takeover（接管）

- "项目做了一半 / 已有工程 / 之前的 AI 帮我做到这了"
- "跳过立项 / 不用从头来 / 方向已经定了"
- "接手别人的项目 / 帮我把这个项目管起来 / 排一下剩下的工作"
- "任务拆解 / 里程碑 / 先读懂我的项目再动手 / 帮我整理一下目录"
- 与 relay 的边界：relay 管**同一项目跨会话**（续接既有协作）；
  takeover 管**接管管理**（接手已推进中的项目，无论出自谁手）。takeover 的换会话收尾仍走 relay
- 与 kickoff 的边界：takeover 管**方向已定**；核验中发现方向其实未定
  （支柱答不上、用户想重做方向）→ 退回 kickoff，不硬接管

### → zhangyi-systems（机制与系统）

- "数值 / 平衡 / 这个机制行不行 / 要不要加某个系统"
- "核心循环细化 / 战斗怎么设计 / 经济系统"
- "这个 buff/卡牌/技能怎么设计 / 新角色新能力"
- "难度曲线 / 惩罚设计 / 奖励节奏"

### → zhangyi-narrative（叙事设计）

- "剧情 / 叙事 / 故事 / 世界观 / 设定"
- "角色 / 人物 / NPC / 反派 / 队友"
- "给 XX 起个名 / 这个命名好不好"
- "剧本 / 对话 / 台词 / 文案 / 教学引导剧情"
- "叙事和玩法怎么结合 / 剧情没人看怎么办"

### → zhangyi-probe（验证探针）

- "模拟一下 / 跑个数据 / 写个探针验证"
- "这个数值成不成立 / 胜率/概率帮我算算"
- "平衡性测试 / 死局率 / 无赢家局"
- "AI 对战跑一万局看看"
- 注意：涉及真人玩家的测试，路由去 zhangyi-playtest，不在本 skill

### → zhangyi-playtest（试飞）

- "找真人测一下 / playtest / 试玩测试 / 找玩家玩玩看"
- "玩家访谈 / 招募测试者 / 封测怎么设计"
- "这个留存数据说明什么 / 流失原因帮我分析"
- "玩家反馈怎么解读 / 测试报告怎么写"
- "试飞 / 真人验证 / 用户体验测试"
- “demo 玩家十分钟就走”这类**已有真人行为或反馈**的问题，先核实样本与口径，
  路由到试飞诊断；若没有可用证据，先给可区分假设与下一次观察动作
- 注意：无真人的模拟验证归 probe；试飞结论也不能证明好玩，
  只证明"这批样本在这个口径下的反应"

### → zhangyi-review（审查收尾）

- "上架 / 发布 / Steam / 送审 / 打包"
- "现在能发了吗 / 发布前检查 / 全面审查一下"
- "权利链 / 素材授权 / 合规"
- "构建 / CI / 存档 靠不靠谱"
- "帮我出一份审查报告"

## 负例（不路由，保持沉默或正常回答）

- 纯编程请求："帮我写个存档系统 / 这个 bug 怎么修"
- 引擎操作："Unity 里怎么做粒子 / Godot 的节点"
- 与游戏无关的对话

张翼是设计陪练，不是编程助手。用户在游戏项目里说"帮我实现 X"时，
不抢编程的活；但如果实现请求里藏着未裁决的设计决定
（"帮我把暴击率改成 20%"——为什么 20%？），用一句话点出，然后让路。

## 复合信号

用户一句话跨多个阶段（"我想做个叙事向肉鸽，帮我看看怎么设计"）：
以**最先需要回答的问题**为准（例句中是立项：先裁决"叙事+肉鸽"这个组合
解决什么病灶，再谈机制）。路由后告知用户你的判断依据。没有配置文件
只表示尚未建档，**不表示已有项目应从零立项**。
