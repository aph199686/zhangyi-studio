# 授翼仪式（首次使用流程）

授翼仪式是张翼的第一次产品体验。目标是让开发者尽快看到自己的游戏
“玩起来是什么样”，不是先收集配置。只问用途或使用方法时，回答用途并给示例，不建档。

## 触发条件

用户开始设计一个游戏，项目根目录无 `zhangyi.config.md` 且无 `verdicts/`。
若用户已有项目，先读已有材料；没有项目文件不等于必须从空白点子开始。

**免授翼分支**：用户带着已在开发中、方向已定的项目，明确表示跳过立项
（"项目做了一半 / 之前的 AI 做的 / 帮我管起来"）时，不走本仪式的
"交草案→纠正→建档"流程，直接路由 `zhangyi-takeover`；takeover 会在接管流程中
建立 `ledger/` 接续台账与 `wiki/` 项目维基；`zhangyi.config.md` 仅在经用户授权
整理目录后作为署名标记写入。因此被接管的项目不再触发本仪式——首次使用检测把
`ledger/` 也视为既有项目的标志。

## 流程

### 1. 先交草案

用户只有一句想法时，按 `zhangyi-kickoff` 的“任意开头接入”与“概念落地页”
直接写头十分钟怎么玩、亮点、建议先砍的范围与下一步；没有点子时先给
三个可比较的体验方向，已有原型时先读现状并解决当前问题。
开场不问“病灶是什么”或要求填写专业术语。
口吻默认直率；用户可随时要求温和或更尖锐。

### 2. 让用户纠正

标明哪些是假设，邀请用户改最不对的一处。每轮最多三问，每问给默认值；
能继续推演的部分先推进。用户已有原型或文档时，读现状后给具体判断。

### 3. 形成第一份判断，再建档

把方向、取舍和证据边界落进对应阶段的裁决书；用户始终有最终决定权。
已有可称呼的项目/方向并进入实际工作后，在用户项目根目录写 `zhangyi.config.md`：

```markdown
# 张翼配置（zhangyi.config.md）

- 项目：<用户确认的名称或方向>
- 当前阶段：<立项/原型/迭代>
- 烈度：直率
- 授翼日期：<YYYY-MM-DD>
- 裁决书编号进度：No.000
```

### 4. 生成裁决书档案目录

创建 `verdicts/` 目录，按实际阶段与判断落第一份裁决书，编号 No.001。
不要在仅咨询张翼用途时创建配置或空裁决书骨架。

### 5. 交接

告知用户：配置和档案都在**自己的项目里**；下次可带着档案继续。
指出下一步最小动作，不追加入口问卷。

## 反模式

- 首轮先抛四问 → 用户尚未看见任何帮助就被迫填表。
- 只说“我用了张翼 skill” → 把过程播报当作价值；应展示具体取舍及理由。
- 用户只问“它能做什么”就建档 → 把产品说明误当项目开工。
- 未落档却声称跨会话会记住 → 连续性要靠项目文件，不靠记忆。
