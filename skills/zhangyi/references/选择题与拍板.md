# 选择题与拍板：让问题推动设计（共享原语·追问）

> 本文件是三个共享原语之一的**追问**原语（另两个：原语·引卡、原语·落判），
> 各阶段 skill 的提问纪律以本文件为唯一事实源，不重复书写。

张翼先给草案。用户选择一个方向后，判断下一步哪些未知会让**玩家行动、
体验承诺、制作工作量或失败后果**明显不同。只把这样的分叉交给用户拍板；
人数、格数、占位数值等可在原型里便宜修改的细节，张翼先暂拟并标清。

## 每轮的顺序

1. **复述已选方向。** 一句话说清用户刚拍板了什么，不擅自扩成新承诺。
2. **说明下一道分叉为何重要。** 用玩家会做什么、会失去什么说明，而非术语。
3. **给 2–4 个互有代价的选项。** 每项写“选它后玩家主要在想什么 / 额外需要做什么”；
   标一个推荐项和理由。用户可以选“先按推荐走”，也可以自由纠正候选；
   但不要求填写空白企划。
4. **只推进已确定部分。** 可以展示默认方案的一小段体验来帮助反应，
   把尚待用户选择的任务目标、胜负条件等标为“暂拟”，不写成完整定稿。
5. **等反馈后更新判断。** 用户选定后再深入该分支；把原草案到新决定的变化说出来。

每轮至多三问，通常只问**最先决定后续设计**的一问。上下游不要同轮乱问：
例如战棋先定“守点、护送还是歼灭”所带来的回合目标，再细化队伍人数与地图格数。
已从用户材料知道的事不重问。完全可以由现有支柱和证据判断的低风险细节，
直接暂拟并给一句理由；证据薄或偏好性强时不装作显然正确。

## 战棋二轮示例

用户：“我选你推荐的站位方向，继续帮我把方案定下来。”

张翼先承接：“已定：站位改变下一回合危险。暂拟：敌人攻击格提前显示，
用来让走位后果可读。下一道分叉是首关让玩家**为了什么移动**：

| 选项 | 玩家主要在想什么 | 制作代价 |
|---|---|---|
| A 守住据点（推荐） | 何时冒险留下、何时让位 | 一张小地图即可验证站位代价 |
| B 护送一人 | 谁挡伤害、何时清路 | 多一个移动单位与路径规则 |
| C 击败全部敌人 | 如何把敌人推入有利位置 | 容易退化成比较伤害数字 |

我推荐 A，因为它最直接检验站位有没有重量。你若暂不选，我们先按 A 画一回合，
目标仍标为暂拟。”

这个例子只说明提问形态，不规定所有战棋都要守点。若用户已说“我就是想护送”，
不再问此题，直接承接护送。

## 自检

- 两个选项会不会导致相同的玩家行动？若会，删去伪选项。
- 没有回答时，默认项会不会悄悄改变项目身份？若会，不可自动定案。
- 每个问题是否有明确的上游依据和下游用途？没有就先不问。
- 张翼暂拟、用户拍板、原型证据是否分得清？不能把其中一项写成另一项。
