# 剧本节奏与工程化

## 剧本质量的三块试金石

### 1. 信息释放顺序

玩家什么时候知道什么，决定了一切。同一段剧情，
信息释放顺序不同，可以是悬念、是反转、是白开水。
检查方法：把剧本里的每个信息点列成表，标注"玩家此刻知道/不知道"——
你不知道玩家此刻知道什么，就没法设计任何一句台词的效果。

### 2. 台词与行动的先后

先说再做（预告）、边做边说（伴随）、做完才说（回味）——
三种时序产生三种完全不同的体验。教学段落尤其敏感：
台词和玩家操作错拍半秒，玩家就不知道自己在干嘛。
评审剧本时逐段标注时序，错拍的挑出来。

### 3. 一步一句的打磨

剧本不是写完的，是调出来的。每个节点问：
这句台词放在这一步，效果是什么？能不能删？能不能提前/延后一步？
能删且没损失的，删——**节奏的本质是密度，不是速度。**

## 多局叙事的赌注链

每局开写前先填五格：**入场前玩家知道什么、这局争什么、赢后哪项世界状态改变、
输后哪项世界状态改变、两路为何都能引出下一局**。状态可以是身份、通行权、
凭据、关系或账目，不必每次都增加一条新支线。若输赢只改一句旁白或余额，
而下一局照常发生且无人回应，这局的叙事功能尚未成立。

汇合不是复位：输后可以换途径取得必要线索，但要留下可见的成本；
赢后可以少付成本或抢到先手，但不能跳过后续全部玩法。把“失去什么”在下注前
说清，结算后让玩家亲手看见变化。随机局的聪明点通常在入局、押注、止损，
不可把随机开奖结果倒写成角色早已算准。

剧情占比大的作品按两层起承转合检查：整段有起承转合，每局内部也有；
上一段的“合”若不能解释下一段为何开场，就补因果接口，而非再加一段设定说明。
这是一种排布工具，不保证情绪有效；真人阅读/游玩仍是最后裁判。

## 仪式感与余韵

关键节点需要仪式设计，让一段体验有郑重的落幕：

- **开局**：玩家做的第一件有仪式感的事是什么？
- **终局/结算**：落幕是"GAME OVER"四个字母，还是一场正式的告别？
  （压暗、留白、逐条呈现——仪式感常常来自"慢下来"。）
- **死亡/失败**：失败是惩罚页面，还是叙事的另一扇门？
  最好的失败设计让玩家觉得"死这一趟，值"。
- **重逢/回归**：玩家隔了很久回来时，游戏怎么迎接 TA？

**氛围是最便宜也最耐用的叙事**：一场循环的雨、固定的光线、
一种环境音——成本极低，但它们让世界在玩家关掉游戏之后还在下。

## 叙事工程化（独立开发者最容易忽略的）

剧本是资产，资产就要可验证：

1. **剧本改动要过门禁**：剧本文件和代码一样会改坏。
   定一条自己的门禁（解析校验、关键路径走读、步骤数基线），
   改剧本必跑，红了回滚。
2. **多语言/多通道一致性**：如果文案有多个载体（对话表、剧情脚本、
   UI 键值），它们必须能机械地对账（diff 为 0），
   不能靠人肉记得"这边改了那边也要改"。
3. **文案与机制一致性**：剧情里说的话，机制必须兑现。
   角色说"这张牌很危险"，它就必须真的危险——
   叙事对机制的承诺不兑现，玩家的信任当场清零。
4. **剧本数据与代码分离**：剧本放在可独立读写的数据文件里，
   写剧本不该需要懂代码——这不只是效率，是让"调剧本"和
   "改逻辑"两种风险永远不混在一起。

## 彩蛋与社区叙事

埋一个"只有懂的人才懂"的东西（兑换码、隐藏文本、反预期的细节）。
它的功能不在游戏内——它给玩家一个"值得截图分享"的瞬间，
是叙事负责传播的部分。少量、精心、不指路。
