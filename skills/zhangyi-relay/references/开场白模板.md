# 通用开场白模板（填空即用）

总长 3~5KB 为宜。宁精勿冗，重复内容只写一遍。

```markdown
# <项目名> 开发会话开场提示词（v<版本号> <日期>）

## 一、项目概览
<一句话定位：类型 + 核心机制 + 运行方式>
<技术栈 + 构建/测试命令>
版本号唯一来源：<文件路径> 的 <字段>，当前版本 <版本号>。
（可选）关键文件速查：
- <路径>：<作用>

## 二、⚠️ 上个会话发生了什么（续接会话必写，新项目可省）
<事故/变更一句话结论，不掩盖>：
1. <发生了什么>
2. <为什么>
3. <教训 → 本次会话的新规则>
当前遗留：<未收尾事项清单>

## 三、本次任务清单（编号，标注状态）
1. <任务>（⚠️ 怀疑未做 / ✅ 疑似已修 / 待核验）
…
<本阶段验收动作>：先<核验/出计划/实机跑>，再<动手>；
证据要<代码位置/截图/数字>。

## 四、红线（严禁触碰）
- <文件/类目> 零改动
- <文件/类目> —— 动前先给方案、确认后再动
- 删除任何文件/目录 —— 先列清单确认
- <从过去事故沉淀的新红线>
- 不许为了让测试变绿而改产品代码；发现真问题如实报告

## 五、门禁与验证（每次改完必跑）
- <命令1> —— 必须 <通过标准>
- <命令2> —— 必须 <通过标准>
- 改<X>后必须 <额外命令>；改<Y>跑 <冒烟命令>

## 六、环境坑（本机/本平台）
- <坑1> → <解法>
- <坑2> → <解法>

## 七、沟通方式
- 我不写代码，方向我口述、你执行；拿不准直接问
- 结论说人话，证据附数字；每完成一小批（<2~3 条>）汇报一次
- 动代码/升版本/删文件前先给方案，确认后再动手

请先熟悉项目和现状（读 <文档1>、<文档2>），<第一步动作>，
全部准备完毕后跟我反馈。
```
