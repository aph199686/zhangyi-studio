# 方案标注规范

每个进入评审的方案按统一格式标注。统一格式的意义：方案之间可以横向比较，
裁决书里可以直接引用，事后复盘能看清"当时依据什么拍的板"。

## 三段式标注

**成本 × 增益 × 侵入度**，各取 低/中/高，附一句话依据。

- **成本**：人力、时间、技术风险。"三天能做完"是低成本；
  "要重写存档系统"是高成本。含不确定性的写"中（依赖 X 验证）"。
- **增益**：对**病灶**的贡献，不是抽象的"好处"。增益必须引用病灶编号：
  "增益高（直接回应 P2：终局无聊）"。引用不了任何病灶的增益 → 装饰章。
- **侵入度**：对现有架构/承诺的破坏程度。
  - 零侵入：纯增量，不动既有系统；
  - 桥接：需要接线/适配，但不改核心逻辑；
  - 需改核心：动核心规则/已发布承诺 → **必须进待拍板清单**。

## 待拍板清单

凡触及以下任一项的方案，不进裁决，先进清单，由用户拍板：

- 改动核心玩法/核心规则文件
- 推翻已对外发布或已对用户承诺的行为
- 引入新的第三方依赖或平台绑定
- 成本评估为"高"且不可逆

清单格式：事项 + 为什么需要你拍板 + 建议（可以附倾向，但标明"建议"）。

## 数值三分类

方案中出现的每个数字必须带分类标记：

- **已验证**：有实验/模拟/上线数据支撑 → 引用证据来源
- **占位**：为了让方案可讨论而暂填 → 标 `[占位]`，禁止参与结论推导
- **待验证**：有理论依据但未实测 → 标 `[待验证]`，列入验证计划

纪律：**占位数字不许穿着"已验证"的外衣出场。**
评审中最常见的自欺就是讨论了三轮之后，所有人都忘了那个数字最初是拍的。

## 反模式

- 只标成本不标增益（显得严谨，实际回避了"值不值"）
- 增益写"提升用户体验"（不可检验，等于没写）
- 侵入度低估（"就改两行"——改的是哪两行的哪一层？）
