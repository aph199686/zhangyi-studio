# 机制活检法（通用版）

分析参考游戏时使用。目的不是"学习成功游戏"，是把一个游戏拆到**可移植的零件粒度**。

## 三步

### 第一步：拆层

把参考游戏拆成 3~6 个机制层。常见拆法（按游戏类型调整）：

| 层 | 问的问题 |
|---|---|
| 信息层 | 玩家知道什么、不知道什么、什么时候知道？ |
| 资源层 | 什么是稀缺的？怎么获得、怎么消耗？ |
| 动作层 | 玩家每回合/每秒能做什么？不能做什么？ |
| 结算层 | 动作如何改变世界状态？谁先谁后？ |
| 终局层 | 怎么赢、怎么输、怎么平局？一局怎么结束？ |

拆层的检验标准：每一层都能独立回答"这层如果换掉，游戏还是不是它自己"。

### 第二步：提炼内核一句话

用一句话说出这个游戏"真正在卖的东西"。
不是题材（"太空探索"），不是类型（"roguelike"），而是**体验的发动机**——
例："用不完整信息逼玩家在赌博与保守之间反复煎熬"。
提炼不出来，说明你还没看懂这个游戏，回去继续拆。

### 第三步：找可杂交把手

内核发动机上，哪些零件是**可以拆下来装到别的车上**的？
可杂交把手的特征：脱离原游戏后依然成立、能映射到你自己游戏的既有结构上。

## 借用纪律（用于原创方向）

用户明确想先做模组、复刻或“像这款游戏的一个版本”时，改走
[从喜欢的游戏起步.md](从喜欢的游戏起步.md)。下列“只借一样”是原创方案的聚焦办法，
不能拿来否定学习性复刻。

- **每个参考游戏只借一样东西。** 借两样以上，你在复制它，不在学习它。
- **每样东西只从一个地方借。** 同一个机制从三个游戏各抄一点，结果是三不像。
- 借来的东西必须回答："它装进我的游戏后，解决我的哪个病灶？"
  答不上 → 这是装饰，不是移植。
- 记录出处。裁决书主张矩阵里写明"借自哪款游戏的哪一层"——
  既是诚实，也方便日后发现"这个灵感源头其实不适合你"时溯源撤回。

## 反模式

1. **抄表面不抄内核**：学《小丑牌》的数字膨胀爽感，不学它"弃牌堆=成绩单"的
   信息反馈结构 → 只得到了膨胀，没得到爽。
2. **印象式分析**：凭游玩记忆写分析，不复盘实际机制 → 拆出来的层是你脑补的。
3. **集邮式借鉴**：五个参考游戏各借一样 → 游戏变成器官拼装怪，没有自己的发动机。
