# 探针纪律（预登记 / 脚本 / 种子 / 复现 / 披露）

## 预登记格式

跑模拟之前，裁决书骨架里必须有这一节，缺一不可：

```markdown
## 预登记
- 假设：<我们期待看到什么，带数字区间>
- 证伪条件：<什么结果 = 否决这个设计>
- 闸门：<点估 + 95% CI 下界 ≥ X%（不用点值做闸门）>
- 样本协议：N = <局数>，种子 = <怎么定>，确认批 = <换种子重跑一次>
```

预登记之后再碰数据。任何"跑完一看，其实我们想测的是另一个指标"
都是拿着结果找理由——发现了就作废重来，不丢人；装作没发生才丢人。

## 探针脚本三律

1. **只读**：探针脚本独立存放（如 `temp/` 或 `probes/`），
   对产品代码零修改。
2. **用真规则**：import 产品的真实规则/引擎代码。
   重新实现"简化版规则"是探针最常见的隐性造假——
   你证明的是你脑中的游戏，不是仓库里的游戏。
3. **留档可复跑**：脚本本身进项目档案，任何人（包括三个月后的你）
   能一条命令重跑出同一批数字。

## 种子与样本量协议

- **种子**：固定并记录种子区间；正式批次用分散种子
  （如按批次哈希派生），避免"挑到一串好看的种子"。
- **样本量**：稀有事件指标（分母小的）在小 N 下测量精度天然不足。
  二项分布指标在分母 n 下的 95% 区间宽度约为 ±2·√(p(1-p)/n)——
  分母 200 时就是 ±7pp。**波动多半是被测量精度包住的，
  不是设计差异。**
- **闸门协议**：正式结论批 N ≥ 5000（按指标稀有度上调），
  报告 95% CI，**下界达标才算过**。
- **"过不过取决于你愿意跑多少局"是危险信号**——说明闸门设计
  有问题，回去改闸门，别加局数硬凑。

## 复现协议

1. **独立复现**：结论被采用前，换种子区间（最好换人/换会话）
   重跑，逐项一致才成立。
2. **确认批**：预登记口径一字不改，新种子批再跑一轮；
   两批一致，结论才许写进裁决书。
3. 复现不一致：先怀疑口径和样本量，再怀疑设计——
   大部分"不可复现"最后都查出是口径漂移。

## 披露规范（错误承认是信用）

发现历史数据有口径错误时，标准动作：

1. **主动披露**：写明错在哪（哪行代码/哪个口径）、影响哪些旧结论；
2. **作废标注**：受影响的旧数字明确标记"作废"，不许继续被引用；
3. **正确口径重测**：给出修正后的数字；
4. 记入裁决书撤回记录。

披露 bug 不掉价——被发现藏 bug 才掉价。
历史上所有高质量的探针迭代，都是靠"我承认上一轮错了"推进的。
