# 两道闸门（结构闸 vs 体验闸）

## 分工表

| | 结构闸门（探针） | 体验闸门（playtest / 判断题） |
|---|---|---|
| 能回答 | 死局率、无赢家率、指标可达性、自洽性、数值区间 | 决策感、戏剧性、爽感、重玩意愿 |
| 工具 | 只读模拟脚本 | 真人试玩 + 开工前判断题 |
| 结论效力 | "这个机制**有效**" | "这个机制**有趣**" |
| 越界警告 | 永远不能说"好玩" | 永远不能说"数值上成立" |

**探针能否决，不能加冕。** 它能便宜地杀死结构上有病的设计
（单 8 废牌型、同归无赢家、线性加成失效——都是探针否决的真实案例），
但它永远不能告诉你哪个方案更爽。

## 历史警示（这类事故的标准形态）

> 某轮迭代中，"裁决率 98.8–100%"（结构事实）差点被当成
> "牌型裁决好玩的证明"（体验结论）。

识别自己正在越界的信号：句子里的主语是探针数据，
谓语却是"爽""好玩""有意思""有味道"——改写句式：
"探针证明它有效；它是否有趣，需要 X 个真人玩 Y 局后回答。"

## 判断题（体验闸门的操作化）

每一期设计工作开工前，先口头回答一组体验判断题，
答不出来的就是本期要验证的目标：

1. 玩家在第几分钟会遇到第一个**真正的抉择**（两个都有道理、
   选了会纠结的）？
2. 这个机制最爽的一瞬间长什么样？说得出画面吗？
3. 玩家输了会怪自己还是怪游戏？（怪自己 = 好设计；
   怪游戏 = 回到可预判性闸门）
4. 连续玩三局，第三局和第一局有什么不同？没有不同 = 重玩性病灶。
5. 如果只能向别人演示 30 秒，你演示哪一段？说不出 = 卖点不清。

判断题的价值：把"体验"从玄学变成一组必须回答的具体问题。
它们不需要数据，需要的是**不许糊弄**。

## 上线前的完整验证链

```
纸面评审（kickoff/systems/narrative 裁决书）
  → 结构闸：探针通过（有效）
  → 体验闸：真人 playtest 通过（有趣）
  → 才允许谈"这个设计成立了"
```

任何一环没做，在诚实声明里写明没做。
跳环吹嘘是这个行业最贵的恶习。
